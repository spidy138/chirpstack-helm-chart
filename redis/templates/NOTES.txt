SECURITY RECOMMENDATIONS
================================================================================

For production:
  1. Change default password IMMEDIATELY
  2. Disable dangerous commands (FLUSHDB, FLUSHALL, etc.)
  3. Use network policies to restrict access
  4. Enable encryption/TLS
  5. Monitor for suspicious activity
  6. Set up automated backups
  7. Configure memory limits and eviction policies

Disable dangerous commands:
  kubectl exec redis-0 -n {{ .Release.Namespace }} -- redis-cli CONFIG SET rename-command FLUSHALL ""

================================================================================
BACKUP & RECOVERY
================================================================================

Manual backup:
  kubectl exec redis-0 -n {{ .Release.Namespace }} -- redis-cli SAVE

Automatic background save:
  kubectl exec redis-0 -n {{ .Release.Namespace }} -- redis-cli BGSAVE

Copy RDB file:
  kubectl cp {{ .Release.Namespace }}/redis-0:/data/dump.rdb ./dump.rdb

For production, implement:
  - Automated RDB snapshots
  - AOF (Append-Only File) replication
  - Redis Sentinel for HA
  - Redis Cluster for scaling

Check disk usage:
  kubectl exec redis-0 -n {{ .Release.Namespace }} -- df -h /data

If out of memory:
  1. Increase maxmemory limit
  2. Configure eviction policy
  3. Clean up unused keys
  4. Check for memory leaks
